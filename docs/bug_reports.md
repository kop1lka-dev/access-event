# Баг-репорты AccessEvent

## BUG-01. [Major] Повторная регистрация с занятым email
- **Серьёзность:** Major
- **Приоритет:** P2
- **Шаги воспроизведения:**
  1. `POST /api/register` с email `test@mail.ru` и валидным паролем
  2. `POST /api/register` ещё раз с тем же email
- **Фактический результат:** сейчас возвращает 400 с сообщением «Email уже занят»
- **Ожидаемый результат:** 400 с понятным сообщением об ошибке (без 500)
- **Статус:** Исправлен
- **Причина:** в `routes/auth.py` реализована проверка
  `if User.query.filter_by(email=email).first(): ... return 400`.
  Без неё `UNIQUE(email)` вызвал бы `IntegrityError` → 500.

## BUG-02. [Major] Регистрация принимает email без @
- **Серьёзность:** Major
- **Приоритет:** P2
- **Шаги воспроизведения:**
  1. `POST /api/register` с email `not-an-email` (нет символа `@`)
- **Фактический результат:** сейчас возвращает 400 «Некорректный email»
- **Ожидаемый результат:** 400 с сообщением о неверном формате
- **Статус:** Исправлен
- **Причина:** в `routes/auth.py` реализована проверка
  `if "@" not in email or "." not in email.split("@")[-1]: ... return 400`.

## BUG-03. [Minor] Повторная регистрация на то же мероприятие возвращает 400 вместо читаемого 409
- **Серьёзность:** Minor
- **Приоритет:** P3
- **Шаги воспроизведения:**
  1. Зарегистрировать пользователя
  2. `POST /api/registrations` с `{"event_id": 1}` — первый раз (успех)
  3. `POST /api/registrations` с `{"event_id": 1}` — второй раз
- **Фактический результат:** возвращает 400 с сообщением
  «Вы уже зарегистрированы»
- **Ожидаемый результат:** 409 Conflict — семантически корректный код
  для конфликта с существующей записью. Клиент по 400 не отличает
  «неверные данные» от «уже существует».
- **Статус:** Не исправлен
- **Причина отсрочки:** изменение контракта API требует согласования
  с фронтендом; отложено до Дня 6.
