# Оценка ИС AccessEvent

## SWOT-анализ

| | Плюсы | Минусы |
|---|---|---|
| **Внутреннее** | **Силы:** инклюзивность на уровне архитектуры (визуальные уведомления, фильтр по инклюзивным мероприятиям, флаг is_deaf); автоматические тесты в CI; контейнеризация через Docker; публикация образа в GHCR | **Слабости:** нет push-уведомлений; тесты идут на SQLite, а продакшен — на PostgreSQL (разное поведение CHECK-ограничений); нет пагинации списка мероприятий; нет чата и отзывов |
| **Внешнее** | **Возможности:** рост аудитории за счёт инклюзивного фокуса; интеграция с календарями и соцсетями; гранты и субсидии на доступные сервисы; партнёрства с НКО | **Угрозы:** конкуренты с мобильными приложениями; изменения требований WCAG; утечка персональных данных; блокировки соцсетей и внешних API |

## Вывод о готовности к опытной эксплуатации

Система готова к опытной эксплуатации в ограниченном контуре:
основные функции реализованы и покрыты тестами (14 автотестов),
развёртывание автоматизировано через Docker и GitHub Actions.

Перед публичным запуском требуется:
- аудит безопасности (ротация SECRET_KEY, HTTPS, rate limiting);
- нагрузочное тестирование;
- переход интеграционных тестов на PostgreSQL;
- подключение резервного копирования по расписанию.

## Направления модернизации

### 1. Push-уведомления о старте мероприятия

**Что:** браузерные push-уведомления (Web Push API) — напоминание
за 30 минут до начала.

**Зачем:** пользователь не пропустит событие, даже если не открыл
сайт.

**Технологии:** Service Worker, VAPID-ключи, Flask + pywebpush.

**Для слабослышащих:** визуальные push-уведомления вместо звуковых —
прямое продолжение инклюзивного фокуса платформы.

### 2. Интеграция с календарём

**Что:** кнопка «Добавить в календарь» на карточке мероприятия
(Google Calendar, iCal, Outlook).

**Зачем:** пользователь получает напоминание стандартными средствами
ОС.

**Технологии:** генерация .ics-файла на сервере, ссылки
`https://calendar.google.com/calendar/render?action=TEMPLATE&...`.

**Для слабослышащих:** не нужно полагаться на слуховые напоминания —
всё делает система.

### 3. Автоматические субтитры для видеоматериалов

**Что:** перевод речи ведущего в субтитры на лету для онлайн-трансляций
и записей.

**Зачем:** прямой доступ слабослышащих к содержанию видеотрансляций
без сурдопереводчика.

**Технологии:** Whisper (OpenAI) или облачные API распознавания речи
(Yandex SpeechKit, Google Speech-to-Text).

**Для слабослышащих:** критичная функция — открывает доступ
к онлайн-форматам, где сурдоперевод обычно недоступен.

### 4. Мобильное приложение (PWA)

**Что:** Progressive Web App — устанавливается как обычное приложение
на телефон, работает частично офлайн.

**Зачем:** удобный доступ с телефона без браузера, push-уведомления
через Service Worker, работа при слабом интернете.

**Технологии:** Service Worker, Web App Manifest, офлайн-кеш
шаблонов и списка мероприятий.

**Для слабослышащих:** уведомления и фильтр инклюзивных мероприятий
всегда под рукой, без необходимости заходить на сайт.
