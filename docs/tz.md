Техническое задание: AccessEvent

1. Назначение и цели

AccessEvent — веб-платформа для организации мероприятий с акцентом на доступность для людей с нарушениями слуха. Цель: обеспечить полный доступ к информации о мероприятиях без необходимости слышать.

2. Описание предметной области

Система работает с сущностями: Event, Participant, Organizer, Registration, Notification, Review, Category. Основные процессы: создание мероприятия, регистрация, визуальные уведомления, чат, отзывы.

3. Требования к функциям

FR-01: Регистрация и авторизация пользователей.
FR-02: Создание мероприятий организатором.
FR-03: Регистрация на мероприятие.
FR-04: Отмена регистрации.
FR-05: Просмотр списка мероприятий.
FR-06: Фильтрация мероприятий.
FR-07: Визуальные уведомления о начале мероприятия.
FR-08: Цветовая индикация статуса регистрации.
FR-09: Текстовый чат.
FR-10: Загрузка материалов мероприятия.
FR-11: Отзывы на мероприятия.
FR-12: Редактирование мероприятия.
FR-13: Отмена или перенос мероприятия.
FR-14: Панель администратора.
FR-15: Статистика для владельца платформы.

4. Требования к качеству

NFR-01: Время отклика системы менее 2 секунд.
NFR-02: Поддержка PostgreSQL 14+.
NFR-03: Python 3.10+, Flask 2.3+.
NFR-04: Соответствие WCAG 2.1 AA.
NFR-05: Адаптивный дизайн.
NFR-06: Пароли хранятся в хешированном виде (bcrypt).
NFR-07: Защита от SQL-инъекций.
NFR-08: Контейнеризация через Docker.

5. Требования к интерфейсу

* Адаптивный дизайн (mobile-first).
* Соответствие WCAG 2.1 AA.
* Цветовая индикация статусов.
* Визуальные уведомления.
* Текстовый чат.
* Шрифт минимум 16 px, высокая контрастность.

6. Требования к данным

* База данных: PostgreSQL 14+.
* ORM: SQLAlchemy.
* Минимум 7 таблиц.
* Пароли хешируются с помощью bcrypt.

7. Технологический стек

* Язык: Python 3.10+.
* Фреймворк: Flask 2.3+.
* База данных: PostgreSQL 14+.
* Шаблоны: Jinja2.
* CI/CD: GitHub Actions + GHCR.
* Тесты: pytest.

8. Ограничения и допущения

* Только веб-версия, без мобильного приложения.
* Нет интеграции с платёжными системами.
* Нет видеоконференций.
* Развёртывание через Docker.
* Срок разработки: 6 дней (36 часов).
